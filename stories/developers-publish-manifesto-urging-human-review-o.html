Developers publish manifesto urging human review of AI-generated work

Category: AI

Software developers and attendees at the AIE Code Summit published a “No AI Slop” manifesto on Nov. 22, urging people to take responsibility for AI-assisted work and review outputs according to the stakes. The signatories warn that AI agents can produce more code and documentation than a person can assess, while unchecked errors can be copied into later work [2]. A study of local open-weight models found that agents often identified the vulnerable code and formed a correct hypothesis but failed to produce a working input that would trigger the vulnerability [9]. Separately, Together AI said an AI coding agent committed a repository credential that enabled an unauthorized party to download stored prompt samples. The company said it was continuing to review potentially exposed customer data [15].

Primary Source: View original article

AI cannot replace human judgement, it can only amplify our judgement (or lack thereof).

— AIE Code Summit 2026 speakers and attendees (GitHub)

Key Points

  • Trace failures: A case study of 100 support-agent traces recorded 12 failures, including seven cases in which the agent asked for details instead of calling a tool and two involving misapplied policy rules [6].
  • Security changes: Together AI said it made zero data retention the default for new accounts, added credential checks to pull requests and changed development rules for AI coding agents [15].
  • Model testing: Researchers tested 12 local model configurations on 10 vulnerability-reproduction tasks. Every configuration handled most of the six easier tasks, while the four harder tasks required the 27-billion-parameter model [9].
  • Review standard: The manifesto argues that success should be measured by what users receive and how it helps them, rather than code volume, merged pull requests or the number of agents running [2].

Perspectives

Together AI: The company said it is investigating what customer information may have been exposed and will notify affected customers directly; it advised customers handling sensitive prompts to enable zero data retention [15].

Sources: Together AI

Technical Details

  • Vulnerability reproduction: The study tested whether agents could turn a vulnerability description into an input that crashes a vulnerable software build, a task researchers describe as closer to test generation than code comprehension [9].
  • Trace grading: EvalSift Lite, a trace-grading tool, validates JSONL agent traces, applies deterministic code checks and generates a Markdown or HTML failure report. It runs without an API key or external dependencies [6].

Industry Impact

  • Software development: The manifesto calls for teams to improve systems and guardrails when a mistake recurs, and to rely on automated checks for problems that linters, type checkers or similar tools can catch [2].
  • AI services security: The stored prompt samples came from requests to the MiniMax M3, GLM-5.2 and Kimi K2.6 models, primarily on June 24, July 4, July 8 and July 14, 2026 [15].

Scientific Significance

  • Performance detail: Quantization did not change which tasks models solved in matched comparisons, though it affected speed; the mixture-of-experts model achieved the same scores in less wall-clock time [9].
  • Limits of evidence: The study used three runs per task under a single testing harness, so its results describe that benchmark rather than all software-development work [9].
