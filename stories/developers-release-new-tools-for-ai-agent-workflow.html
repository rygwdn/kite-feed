Developers release new tools for AI agent workflows

Category: AI

Developers released a set of AI-agent projects aimed at recurring problems in agent work: memory, coordination, observability, local automation, hardware access and interview assistance [1][2][3][4][5][6][7][9][10]. Several projects describe themselves as open-source or repository-based tools, including Kage, Argybargy, Agent-historian, Ratchet, FERNme and Flue [1][3][5][6][7][9]. Kage says it gives coding agents shared, Git-native memory by writing lessons into a repository and checking citations against code before stale or deleted references mislead an agent [1]. Agent-historian addresses a similar statelessness problem by letting agents search prior OpenCode and Claude Code sessions from the command line without modifying the underlying data stores [5]. FERNme describes a user-owned memory layer designed to update with near-zero LLM calls and keep recall token-flat as agents act across domains such as websites, support, booking and tutoring [7]. Other projects focus on production and infrastructure. Moduna describes itself as analytics for AI agents, clustering production conversations into user goals, friction and unmet demand while flagging non-resolution, frustration and blind spots [2]. Argybargy offers a peer-to-peer HTTP relay for agents across machines, apps and model vendors [3]. Ratchet combines BIOS and SPI-flash tooling with a built-in JSON-RPC MCP server for AI agents. Flue offers a TypeScript harness for autonomous agents, and Stepyard adds LLM steps to local YAML automation pipelines [6][9][10].

Key Points

  • Repository memory: Kage advertises a "100/100 trust benchmark," zero dependencies, no account or API key, and a sample receipt showing 412,000 tokens saved in one week [1].
  • Local protocols: Argybargy says any agent that can make HTTP calls can join a room through a URL and code, with plain JSON messages, long-polling replies, per-agent keys and rate limits [3].
  • Automation stack: Stepyard runs YAML pipelines through a CLI or local daemon, extends workflows with Python functions and includes an llm.generate step for tasks such as summarizing deploy results [10].
  • Specialized hardware: Ratchet targets CH341A and CH347 USB programmers, marks commands as live, offline or not wired, and says unsupported live transports exit non-zero rather than faking success [6].

Technical Details

  • Agent-historian storage access: Agent-historian reads OpenCode’s opencode.db and Claude Code project JSONL files, uses Node’s built-in node:sqlite in Node 22.5 or newer, and ships with zero runtime dependencies [5].
  • Argybargy message contract: Argybargy exposes a self-documenting GET / manifest plus POST /messages and GET /messages?wait= endpoints, with an expects_reply field set to none, anyone or a named peer to manage turn-taking [3].
  • Ratchet runtime design: Ratchet is written as a single Rust binary using custom libusb FFI and a custom JSON-RPC MCP server, avoiding Node or Python runtimes [6].

Action Items

  • Test Kage without installing it: Run npx -y @kage-core/kage-graph-mcp scan --project in a repository to try its scan mode before installation [1].
  • Inspect past agent sessions: Install Agent-historian’s ochist CLI and run project-scoped searches first, using --global only when you need results beyond the current directory [5].
  • Run a local Stepyard flow: Install with pip install stepyard, then run stepyard init my-project and stepyard run hello from the generated project [10].
