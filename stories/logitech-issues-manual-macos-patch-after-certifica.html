Logitech issues manual macOS patch after certificate lapse

Category: Technology

Logitech says an expired Developer ID certificate caused its Logi Options+ and G HUB apps on macOS to stop launching, which in turn reset many Logitech mouse and keyboard features back to default behavior for affected users this week [1][8][6][9][11]. Logitech has published updated versions for macOS 26 Tahoe, 15 Sequoia, 14 Sonoma, and 13 Ventura, but users must install the fix manually because the same certificate problem also broke the apps’ built-in updaters [1][9]. Logitech apologized publicly and said customer profiles and customizations should remain intact after applying the update, turning a frustrating hiccup into a recoverable, “no data lost” kind of repair [1][8].

Primary Source: View original article

We dropped the ball here. This is an inexcusable mistake. We’re extremely sorry for the inconvenience caused.

— ATXsantucci (Logitech spokesperson, per the post) (MacRumors)

Did you know: Apple’s Developer ID certificates are issued for a fixed term (commonly five years) and must be renewed to avoid app disruptions [9].

Key Points

  • What broke: Reports described failures ranging from apps refusing to open to some Macs getting stuck in an apparent launch/boot loop because the expired certificate was used to secure inter-process communications inside the software [1][3].
  • Who felt it: Owners of Logitech peripherals such as MX Master-series mice and MX Keys keyboards reported losing access to scrolling tweaks, button mappings, and gesture controls when the companion apps failed [1][11][12].
  • How to fix: Multiple outlets pointed users to Logitech’s downloads for updated Logi Options+ and G HUB installers, emphasizing you may need a direct manual download rather than relying on in-app update prompts [9][2][12].
  • Older macOS: Logitech’s support messaging indicated older macOS versions outside the listed releases would receive a fix later, suggesting a staggered remediation for people on legacy systems [1].

Perspectives

Logitech: The company attributed the outage to an inadvertently expired certificate, apologized, and directed users to manually install updated app versions because the in-app updater was also impacted.

Sources: MacRumors

Affected Mac users: Users described sudden loss of custom mouse/keyboard behavior and turned to community forums and social media to troubleshoot and share workarounds while waiting for a fix.

Sources: The Register

Independent Mac developers/commentators: A developer blog pushed back on common misconceptions circulating about what the certificate expiration does (and does not) imply for security or system integrity, aiming to clarify the technical narrative.

Sources: Lapcat Software

Timeline

  • Monday: Logi Options+ and G HUB stopped launching for Mac users [8].
  • Yesterday: Users reported losing Logitech customization controls across macOS [1].
  • January 8, 2026: Logitech reiterated the expired certificate cause and apology [3].

Technical Details

  • Developer ID certificate: A Developer ID certificate is Apple’s code-signing credential that helps macOS validate a developer’s software; outlets reported Logitech’s lapse prevented the apps from running normally [9][6].
  • In-app updater dependency: Because the same certificate issue affected Logitech’s updater mechanism, the usual “update available” path couldn’t deliver the fix, forcing a manual installer workflow [1][8][2].
  • Inter-process communications: MacRumors reported the expired certificate was used to secure inter-process communications, and its failure kept components from starting correctly in some cases [1].

Industry Impact

  • Peripheral software ecosystems: The incident highlights how modern mice and keyboards increasingly depend on configuration apps for full functionality, meaning software signing and update pipelines have become operationally critical for hardware brands [1][11][common].
  • Mac enterprise IT: Because the fix requires manual installation (not in-app updating), managed Mac fleets may need extra help-desk effort and distribution planning to restore standard input-device behavior for staff [1][2][common].
  • Platform security norms: Coverage underscored that Apple’s code-signing enforcement can surface as a user-facing reliability issue when certificates expire, reinforcing why vendors treat signing and renewal as part of secure software supply-chain hygiene [6][9][common].

Historical Background

macOS uses code signing (including Apple-issued Developer ID certificates) to verify that software comes from an identified developer and hasn’t been tampered with [common]. Developer ID certificates have finite lifetimes and must be renewed; when they lapse, apps that depend on them for launch or internal trust checks can fail in ways that look like sudden “it worked yesterday” outages [9][common].

Q&A

Q: Why did some users see an apparent boot/launch loop instead of a simple app crash?

A: MacRumors reported the expired certificate affected inter-process communications, which could prevent components from starting correctly and, in some cases, lead to an endless boot/launch loop behavior [1].

Q: Which macOS releases did Logitech explicitly list as supported by the patch?

A: Logitech published updated versions for macOS 26 Tahoe, macOS 15 Sequoia, macOS 14 Sonoma, and macOS 13 Ventura [1][9].

Q: Is there reporting that the incident erased users’ saved settings?

A: Multiple reports said settings should survive: Logitech indicated profiles/customizations remain intact after manual patching [1][8].

Action Items

  • Manually install Logitech’s updated app: Download the latest Logi Options+ or G HUB installer from Logitech and run it without uninstalling first, since Logitech warned the updater was also affected by the expired certificate [1][9].
  • Confirm your profiles restored: After updating, open Logi Options+ or G HUB and verify button mappings/gestures; Logitech indicated profiles and customizations should remain intact post-fix [1].
