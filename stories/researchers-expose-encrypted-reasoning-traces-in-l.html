Researchers expose encrypted reasoning traces in LLM APIs

Category: AI

Researchers Alexander Panfilov, David Schmotz, Ilia Shumailov, Luca Beurer-Kellner, Joachim Schaeffer, Ameya Prabhu, Jonas Geiping and Maksym Andriushchenko published a paper submitted Aug. 10 describing a method to recover concealed chain-of-thought traces from proprietary large language model APIs [2][3]. The paper says leading providers hide step-by-step reasoning to protect intellectual property and limit information leakage, but return encrypted reasoning blocks to clients for reuse in later requests instead of keeping them only on their servers [2][3]. The authors say encrypted reasoning blocks can work across different sessions, users and models within the same provider ecosystem. They describe a “scalable decryption jailbreak” in which an encrypted trace from one model is injected into a weaker model that then outputs the trace in plaintext [2][3]. They report demonstrations across Anthropic, OpenAI and Google, and say the flaw can support anti-distillation bypasses, private-data extraction, hazardous-content disclosure from hidden reasoning, and prompt injections embedded inside encrypted blocks [2][3]. Semantica, a separate AI infrastructure project, describes itself on GitHub as open-source, self-hostable graph-native infrastructure for context graphs, knowledge graphs, graph analytics, causal reasoning and decision provenance, aimed at high-stakes and regulated domains [1]. The repository page listed 7,000 stars, 732 forks, 2,318 commits and an MIT license at publication time [1].

Primary Source: View original article

By injecting an encrypted reasoning trace from a given model into a weaker, and less safeguarded model from the same provider, we force it to decode and output the trace verbatim in plaintext, without ever jailbreaking the more capable model directly.

— Alexander Panfilov, David Schmotz, Ilia Shumailov, Luca Beurer-Kellner, Joachim Schaeffer, Ameya Prabhu, Jonas Geiping and Maksym Andriushchenko (arXiv)

Key Points

  • Disclosure: The authors say they followed responsible disclosure and propose cryptographic and system-level mitigations for client-side reasoning traces [2][3].
  • Traceability tooling: Semantica’s repository lists RDF and labeled-property-graph support, W3C standards, ontology management and end-to-end traceability among its core design claims [1].

Industry Impact

  • Developer security: Developers who publish session logs may expose hidden encrypted blocks that contain recoverable private data, including the PII and credentials found in the authors’ repository scrape [2][3].

Action Items

  • Audit shared AI session logs: Search public repositories and support artifacts for encrypted reasoning blocks or API transcript dumps before publishing or archiving them [2][3].
  • Separate reasoning state by context: API designers should bind encrypted reasoning artifacts to the originating user, session and model so they cannot be replayed across contexts [2][3].
  • Review traceability requirements: AI procurement teams should require documentation on provenance, auditability, self-hosting options and vendor-lock-in before deploying agent infrastructure in regulated workflows [1][common].
